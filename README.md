# GameMasterStudio

**ゲームのマスターデータ編集を、表計算の手軽さで。
何を変えたかの確認と共有を、Gitで。**

敵のステータス、アイテム一覧、ステージ設定。

GameMasterStudio は、ゲームを支えるCSVを見やすい表で編集し、変更内容を確認しながらGitで管理できるデスクトップアプリです。

表計算ソフトのように値をまとめて編集しながら、

* どの敵のHPを変更したか
* どのアイテムを追加・削除したか
* リリースに向けて、どのデータが変わっているか

を、CSVのテキスト差分ではなく、行やセル単位で確認できます。

Gitのコマンドを覚える必要はありません。
ブランチの作成、変更の確認、コミット、Push、チームの変更とのマージまで、GameMasterStudioから操作できます。

**表計算の編集しやすさと、Gitの変更管理をひとつに。**
Gitに詳しくないプランナーでも、マスターデータの変更を追える形で管理できます。

## できること

* **表計算のように、まとめて編集。**
  コピー＆ペースト、連番のオートフィル、行の一括複製に対応。検索やフィルターで対象を絞り、Undo / Redoでやり直せます。

* **何を変えたかを、データとして確認。**
  追加・変更・削除を色分けし、セルごとの変更前後を確認できます。
  たとえば `hp: 100 → 120` のように、CSVの行番号ではなく、敵やアイテムなどのデータ単位で差分を確認できます。

* **変更をGitの履歴に残す。**
  編集内容をコミットとして残すことで、いつどんな変更を行ったかを追えるようにします。
  前回のリリースからどのマスターデータが変わったかを確認するための履歴としても利用できます。

* **調整の意図を、データのそばに残す。**
  テーブル・行・セルにコメントを付けられます。
  「この敵のHPを上げた理由」「QA後に再確認したい値」といった情報を、対象のデータと一緒にGitで管理できます。

* **Gitに詳しくなくても、チームで変更を共有。**
  ブランチの作成、コミット、Push、更新の取り込みをアプリから操作できます。
  ターミナルでGitコマンドを入力する必要はありません。

* **競合しても、CSVを直接直さない。**
  チームメンバーと同じデータを変更していた場合も、CSVのコンフリクト文字列を直接編集する必要はありません。
  GameMasterStudio が行・セル単位で変更を比較し、自動でまとめられる変更は自動マージ。本当に判断が必要な値だけ、自分と相手の変更を比較して選べます。

データはローカルのCSVとして保存され、コメントやプロジェクト設定も同じGitリポジトリで管理します。

## 基本的な使い方

GameMasterStudioでは、マスターデータの編集からGitへの保存までをひとつの流れで進めます。

```text
作業用のブランチを作る
        ↓
マスターデータを編集
        ↓
変更内容を確認
        ↓
コミット
        ↓
Pushしてチームに共有
        ↓
他のメンバーの変更を取り込む
```

Gitの細かな操作を覚えなくても、この流れをアプリ上から進められます。

## 使ってみる

現在はソースから起動できます。

必要なもの：

* Node.js 20.19+ / 22.12+
* pnpm
* Rust stable
* Git CLI
* お使いのOSの[Tauri開発環境](https://v2.tauri.app/start/prerequisites/)

このリポジトリをクローンし、そのフォルダで実行します。

```sh
pnpm install
pnpm tauri dev
```

### 最初のテーブルを作る

1. **Project を初期化**から、データを保存するフォルダを選びます。

2. **Branch を作成**で作業用ブランチを作ります。
   `main`などの保護ブランチは閲覧専用です。

   名前とメールアドレスを求められた場合は、**Project Settings**の**Git Identity**から設定できます。Gitの設定ファイルを直接編集する必要はありません。

3. **Master を作成**でテーブルを定義します。

   たとえば、敵のデータなら次の設定で始められます。

   | 項目                   | 入力例                    |
   | -------------------- | ---------------------- |
   | ID                   | `enemy`                |
   | CSV path             | `masters/enemy.csv`    |
   | Columns（1行に1つ）       | `enemy_id`、`name`、`hp` |
   | Primary Key（行を識別する列） | `enemy_id`             |

4. 行を追加して値を入力し、**新規行を保存**で確定します。

   その後のセル編集は自動保存されます。

5. **Change Review**を開くと、今回変更した内容を確認できます。

   たとえば、

   ```text
   Enemy / 1001

   hp
   100 → 120
   ```

   のように、どのデータのどの値を変更したかを確認できます。

6. 内容に問題がなければコミットします。

   必要なら、そのままPushしてチームに共有できます。

あとは敵を複製してバリエーションを作ったり、HPをまとめて調整したり。

いつもの表計算に近い感覚で編集しながら、変更はGitに残していけます。

## GameMasterStudioが目指すもの

ゲームのマスターデータは、日々たくさんの値が変更されます。

表計算ソフトは編集には便利ですが、

**「今回のリリースで、結局どの値が変わったのか」**

を確認する用途には向いていません。

一方でGitは変更管理に強力ですが、CSVの差分は読みづらく、Gitそのものの操作にも知識が必要です。

GameMasterStudio は、

**表計算のように編集し、
ゲームデータとして差分を確認し、
Gitで変更を残す。**

この一連の作業を、プランナーでも扱いやすいひとつのアプリにまとめることを目指しています。

## Column Script

Master の「ƒ Column Script」、または列ヘッダーの「Set Script / Edit Script」から、列ごとに JavaScript を設定できます。例えば `power` 列に次の定義を保存すると、各行の `attack` と `defense` から値を計算します。

```js
return Number(row.attack) * 2 + Number(row.defense);
```

`row` に渡されるのは同じ行の **通常列の文字列**だけです。Script 列は入力に含めず、別行・別Masterを参照するAPIはありません。戻り値は string / number / boolean を文字列に変換します。空文字は `return "";` で返してください。

* 通常セルの編集・貼り付け・Fillで、その行のScript列を再計算します。Script定義の追加・変更では、その列の全行を再計算します。
* Scriptセルは青、手動上書きしたセルは黄色で表示します。上書きしたセルは以後の再計算から除外します。セルの右クリックメニュー「Remove Override」で計算値に戻せます。
* 行の追加・複製時はScriptを計算します。複製元のPrimary Key・Script値・Manual Override・コメントはコピーしません。Scriptを持つMasterでは、保存済み行のPrimary Keyは変更できません。
* Scriptを削除すると現在値を維持した通常列に戻ります。計算結果・定義・Overrideは同じ操作として自動保存し、Undo / RedoではScriptを再実行せず、その操作の前後の状態を復元します。
* CSVには計算済みの値を保存します。定義とOverrideは `gamemasterstudio/scripts/<master-id>.json` に保存し、Changes画面からCSVと一緒にCommitできます。Script metadataの競合は自動解決せず、アプリから開始したMergeを中止して元の状態へ戻します。

通常モードでProjectやBranchを開くと再計算します。既存の閲覧専用ルールは維持するため、Protected BranchやGit Identity未設定の状態で計算結果に差分が出た場合は保存せずエラーを表示します。Working Branchを作成し、Identityを設定して再計算してください。

Scriptは信頼できる開発者が記述するJavaScriptとしてUIスレッドで実行します。Sandbox・Worker・timeoutはありません。無限ループなどで通常起動できなくなった場合はアプリを再起動し、Launcherまたは最近のProjectの **Safe Mode** から開いてください。Safe Modeではコンパイルも実行もせず、CSVの現在値を表示したまま定義を修正・保存できます。JSONとして読める不正なmetadataはColumn Script画面で修正できます。JSON自体が壊れている場合はファイルを修正してください。修正後はProjectを閉じ、通常モードで開き直します。
